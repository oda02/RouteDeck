# Naive Proxy: поддержка и проверка

Проверено 5 сентября 2026 года для закреплённого в RouteDeck **sing-box 1.13.21**.
Наличие поддержки протокола не означает, что конкретный сервер доступен или его
учётные данные верны.

## Импорт

В форме «Добавить сервер» можно вставить ссылку:

```text
naive+https://user:password@example.test:443#My%20Naive
naive+quic://user:password@example.test:443#My%20Naive
```

Это вымышленные примеры. Зарезервированные символы в имени пользователя и пароле
нужно кодировать как компоненты URL: например, `@` → `%40`, `:` → `%3A`, `%` → `%25`.
Если порт пропущен, используется 443. Имя пользователя и пароль указываются вместе.
Поддерживаются также списки ссылок, их Base64-представление и поддерживаемые
объекты outbound из sing-box JSON. Обычный конфиг отдельного клиента NaiveProxy
с полем `proxy` имеет другой формат и не является sing-box JSON.

TLS-проверка сертификата обязательна. Параметры `insecure`, произвольные пути к
сертификатам и неподдерживаемые расширения не принимаются. Ссылка использует имя
сервера как TLS-имя; для отдельного `server_name` нужен sing-box JSON.

Исправлена обработка IPv6 в ссылках: скобки из URL вида `[2001:db8::1]` больше
не передаются в поле адреса сервера. Регрессионные тесты в `subscription.rs`
проверяют это для Naive HTTPS/QUIC, Hysteria2 и VLESS, а также декодирование
учётных данных и порт по умолчанию для обоих вариантов Naive.

## Что проверено

- Хеши `sing-box.exe` и `libcronet.dll` соответствуют `engine/sing-box.lock.json`.
- Команда `version` подтверждает 1.13.21 и возможности `with_naive_outbound`,
  `with_purego`.
- Два синтетических конфига Naive, с HTTPS и с QUIC, успешно прошли
  `sing-box check`. Проверялись представительные поля outbound, без запуска
  слушателей, TUN, изменения сетевых настроек или соединения с сервером.

На Windows DLL должна находиться рядом с исполняемым файлом sing-box; portable
сборка включает оба файла. `check` подтверждает принятие конфигурации ядром,
но не проверяет запуск Cronet, TLS-рукопожатие и доступность сервера. Это
проверяется обычным подключением пользователя и HTTPS-пробой RouteDeck.
Тестировать настоящий сервер поверх другого VPN следует с учётом его маршрутов;
в ходе описанной проверки другой VPN не изменялся.

## UDP и переподключение игр

По умолчанию Naive в RouteDeck проксирует **TCP**. `naive+quic` выбирает QUIC для
связи с прокси, но сам по себе не добавляет поддержку UDP приложений.

В **Правила → Дополнительные настройки Naive → UDP over TCP для Naive** можно
включить SagerNet UoT v2. Это сохраняемая настройка для всех профилей Naive;
активный Naive переподключается после изменения. Другие протоколы не затрагиваются.
RouteDeck передаёт только `udp_over_tcp: { enabled: true, version: 2 }`; при
выключенной настройке поле отсутствует. Импорт узлов эту настройку не включает.

На сервере должна быть совместимая обработка UoT v2 (например, sing-box).
Обычного Naive-сервера без этой поддержки недостаточно. Для UDP приложений
используйте TUN. Правила трафика остаются в силе: включённая блокировка UDP 443
продолжает блокировать этот порт и при UoT. Для проверки UDP именно на порту 443
нужно явно выключить соответствующее правило; для других портов это не требуется.

Успешная HTTPS-проверка через Naive не доказывает работоспособность игрового UDP.
Структура UoT, выключенное состояние, применение только к Naive, переподключение
и строгая проверка в helper покрыты синтетическими тестами. Проверку настоящего
UDP на настроенном пользователем сервере выполняет пользователь отдельно.

При смене VPN-сервера меняется сетевой путь и может измениться внешний адрес.
Существующая игровая сессия может перестать работать, пока игра не создаст новую;
обновление страницы браузера обычно создаёт новое соединение. Это возможное
объяснение симптома Rocket League, а не установленная причина конкретного случая.
RouteDeck создаёт новый процесс ядра при новом подключении, но не может обещать
сохранение сессии сторонней игры. Для диагностики полезно сравнить повторный вход
в онлайн-режим и перезапуск игры после завершившегося подключения VPN.
