## Что изменилось в 0.1.4

- Длительные ошибки проверки захвата TUN теперь учитываются при восстановлении. После шести неудачных проверок с обычным интервалом в 10 секунд RouteDeck может перезапустить своё ядро через уже подтверждённый helper. Краткий сбой сохраняет текущую сессию без перезапуска и нового запроса UAC.
- Ошибка проверки захвата сразу сбрасывает прежнюю успешную проверку и её задержку. После перезапуска статус «Подключено» появляется только после свежей проверки слушателей, выбранного выхода и трафика через принадлежащий сессии TUN.
- Изменение метрик маршрутов больше не блокирует перезапуск уже подтверждённой сессии из-за снимка, сохранённого перед первоначальным запросом UAC. Перед каждым перезапуском RouteDeck проверяет завершение своей прежней сессии, тот же физический адаптер и DNS, текущий маршрут и отсутствие чужого полного туннеля.

## Проверка и ограничения

Изменение выбранного адаптера или его DNS приостанавливает автоматические попытки. Если завершение TUN нельзя подтвердить, RouteDeck сохраняет сведения о сессии для восстановления и блокирует новое подключение.

Исправленные пути воспроизведены на детерминированных локальных фикстурах. Поведение после длительного сна на реальном подключении и точная причина сообщённого сбоя не подтверждены этими проверками. Защита от прямого выхода трафика при остановке ядра и восстановлении TUN пока не реализована.

Для обновления с 0.1.3 доступен подписанный механизм полного portable-комплекта. С 0.1.2 и более ранних версий скачайте полный Windows x64 ZIP и распакуйте его в новую папку. Не смешивайте компоненты разных версий; подписки и настройки остаются в данных пользователя Windows.
