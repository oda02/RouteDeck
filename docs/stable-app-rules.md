# Правила приложений после обновлений

## Поведение и выбор

Старые и новые правила по умолчанию используют **точный путь**. Чтобы правило
переживало смену папки версии, нажмите имя приложения в «Правилах», выберите
**«Имя файла · после обновлений»**, добавьте изменение в черновик и нажмите
«Применить правила». До общего применения соединение не меняется.

Имя файла совпадает независимо от папки и регистра. Это не проверка издателя,
подписи или идентичности приложения: другая программа с таким же именем тоже
совпадёт. Точные пути применяются перед более широкими правилами по имени.
Повторное правило с тем же сопоставлением запрещено; точный путь и имя могут
сосуществовать. «По умолчанию» не создаёт правила движка.

Для надёжного разделения приложений нужен **TUN**. Системный прокси охватывает
только TCP приложений, использующих прокси Windows. Правило не захватывает
автоматически дочерние процессы с другими именами и не меняет уже открытые
соединения. Если движок не определил процесс, применяется остальная политика
маршрутизации; это не механизм проверки безопасности приложения.

## Codex / ChatGPT и Discord

При ограниченном чтении имён запущенных процессов подтверждены `ChatGPT.exe`
для интерфейса Codex и отдельный `codex.exe` для агента. Для этих двух процессов
нужны два правила по имени; правило `ChatGPT.exe` может охватывать и другой
клиент с таким же именем. `Discord.exe` также подтверждён, без предположений
о названиях остальных процессов Discord. Пути машины, аргументы, окружение и
пользовательские данные не записывались в репозиторий. Названия могут измениться
в будущих выпусках: проверяйте список запущенных приложений после таких изменений.

## Почему движку передаётся шаблон

Закреплён sing-box **1.13.21**. Его [правила маршрутизации](https://sing-box.sagernet.org/configuration/route/rule/#process_path_regex)
поддерживают сопоставление имени и пути в Windows. Однако [реализация process_name](https://github.com/SagerNet/sing-box/blob/628cb31ffa79cffffd34c2f9cde6cae044e4fc12/route/rule/rule_item_process_name.go)
ищет basename в таблице с учётом регистра. Поэтому режим имени компилируется
в `process_path_regex`: `(?i)(?:^|[\\/])ChatGPT\.exe$`.

Это сгенерированный литерал: только валидное имя `.exe`, до 260 байт UTF-8,
без разделителей, ADS, управляющих символов, wildcard и зарезервированных
имён Windows. Все метасимволы экранируются. Привилегированный помощник
декодирует и повторно генерирует выражение, требуя точного совпадения; произвольный
regex через IPC или конфигурацию недоступен. Нормализация дубликатов консервативно
сворачивает регистр Unicode; некоторые разные Unicode-написания могут считаться
дубликатом, чтобы избежать неоднозначного порядка правил.

[Движок](https://github.com/SagerNet/sing-box/blob/628cb31ffa79cffffd34c2f9cde6cae044e4fc12/route/rule/rule_item_process_path_regex.go)
компилирует выражение при создании правила и проверяет найденный путь процесса
для маршрутизируемого соединения. RouteDeck не добавляет периодическое
перечисление процессов. [Синтаксис Go regexp](https://pkg.go.dev/regexp/syntax)
определяет `(?i)` и конец текста `$`: многострочный режим не включён, поэтому
суффикс и дополнительная строка не входят в совпадение. Unicode-регистр следует
семантике Go regexp, а не правилам проверки идентичности Windows.

## План и проверка

- [x] Старое хранилище и IPC без `matchBy` сохраняют точные пути.
- [x] Типизированный выбор `path` / `name`; закрытая проверка в renderer, Rust и helper.
- [x] Компиляция буквального basename; точные пути имеют приоритет.
- [x] Черновик, отмена, единое применение и сохранение выбора после перезапуска.
- [x] Детерминированные тесты миграции, дубликатов, IPC, compiler и hostile input.
- [x] Browser preview с синтетическими приложениями, без native backend или движка.

Реальный TUN и активное подключение не запускались и не изменялись. Проверка
реального определения процессов остаётся для отдельного изолированного Windows
сеанса после проверки безопасности, а не для unit-тестов на рабочей машине.
