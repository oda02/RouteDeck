# Варианты обновления RouteDeck

Исследование на 26 сентября 2026 года. Это предложение для выбора; обновлятор,
новые зависимости, сертификаты и ключи в этом PR не добавляются.

**Удобное обновление portable возможно. Переход на установщик необязателен.**
Для основного канала рекомендую установку **для текущего пользователя через NSIS
и стандартный Tauri updater**, сохранив portable отдельным вариантом. Так меньше
собственного кода замены файлов. Если принципиально сохранять только portable,
реализуем проверенное скачивание и замену после выхода отдельным процессом.

## Что есть сейчас

`src/appUpdates.ts` проверяет стабильную версию при запуске и каждые шесть часов.
`src-tauri/src/app_updates.rs` использует фиксированный GitHub API, ограничивает
размер/время ответа, отклоняет редиректы и посторонние release URL. Кнопка открывает
страницу релизов: загрузки и установки из приложения нет.

В `tauri.conf.json` упаковка выключена (`bundle.active=false`). CI выпускает полный
ZIP с GUI, TUN helper, sing-box/Cronet, Xray, лицензиями и ссылками на соответствующие
исходники. `build-local-portable.ps1` встраивает SHA-256 конкретного helper в GUI;
`package-controller.ps1` проверяет финальные байты. Helper ищется рядом с GUI,
движки — в фиксированных `engine`/`xray`. Обновлять только `routedeck.exe` нельзя.
Подписки, настройки и журналы сессий находятся в данных пользователя Windows;
смена папки приложения уже поддерживается инструкцией portable-релиза.

`SHA256SUMS.txt` защищает от повреждения, но не от замены архива и контрольных сумм
одним атакующим. В проверенных release-скриптах нет независимой подписи обновлений
или Authenticode signing stage. Их потребуется добавить до автоматического запуска.

## Три пути

| Вариант | Что видит пользователь | Сложность и ограничения |
| --- | --- | --- |
| Portable: скачать и открыть папку | «Скачать новую версию» → прогресс → проверенный архив/распакованная новая папка. Пользователь закрывает старую версию и запускает новую. | Самый короткий этап; не требует замены работающих файлов, но остаётся ручной запуск. |
| Portable: обновить с перезапуском | «Обновление готово» → установка после отключения → приложение запускается снова. | Собственные updater-процесс, журнал замены, проверка каждого файла, восстановление после сбоя, ограничение папок и тесты Windows. |
| NSIS для пользователя + Tauri updater | Один первоначальный setup; дальше скачать в приложении и установить с перезапуском. Portable остаётся доступен. | Стандартная установка; адаптировать нашу проверенную упаковку, добавить подписи и update metadata. Откат данных и безопасное отключение всё равно наши задачи. |

Tauri updater на Windows использует NSIS/MSI и обязательную подпись; публичный
ключ закрепляется в приложении. Это не готовая замена нашего произвольного portable
ZIP. Проверку, скачивание и установку можно разделить. Метаданные можно разместить
в GitHub Releases, отдельный сервер не обязателен.
[Tauri updater](https://v2.tauri.app/plugin/updater/).

NSIS `installMode: "currentUser"` устанавливает приложение для текущего пользователя
в доступную ему папку; `perMachine` требует администратора. Это отдельно от
`plugins.updater.windows.installMode` (`passive`/`basicUi`/`quiet`), управляющего
интерфейсом обновления. Обычный RouteDeck остаётся без повышения прав; TUN по-прежнему
запрашивает UAC при подключении, сервис не устанавливается.
[Tauri Windows installer](https://v2.tauri.app/distribute/windows-installer/#install-modes),
[конфигурация NSIS](https://v2.tauri.app/reference/config/#nsisinstallermode).

## Обязательные условия для любого автоматического пути

1. **Подлинность.** Закрепить update public key в доверенной версии приложения.
   Подписывать весь пакет либо подписанный манифест с версией, архитектурой, размером
   и digest пакета; после проверки подписи проверять каждый распакованный файл.
   Ключ не брать из скачанного JSON. Private key — защищённый release-secret с
   резервной копией, без доступа из PR сборок. Продумать ротацию через ранее
   доверенную версию; отсутствие подходящей подписи останавливает обновление.
2. **Подпись Windows — отдельная задача.** Authenticode подтверждает издателя EXE;
   она не заменяет подпись пакета updater. Покупка сертификата не обязательна для
   Tauri update signature, но помогает распространять приложение. Даже подписанная
   новая версия может вызвать SmartScreen; обещать отсутствие предупреждений нельзя.
   [Microsoft: репутация SmartScreen](https://learn.microsoft.com/en-us/windows/apps/package-and-deploy/smartscreen-reputation),
   [Tauri: подпись Windows](https://v2.tauri.app/distribute/sign/windows/).
3. **Не прерывать активный туннель.** Скачать можно заранее, установить по умолчанию
   только после явного отключения пользователем. Не снимать защиту от прямого выхода
   ради фонового обновления. Перед установкой остановить новые операции/retry,
   восстановить только принадлежащее RouteDeck состояние, проверить восстановление,
   дождаться завершения своих процессов. При конфликте/ошибке ничего не устанавливать.
   «Отключить и обновить» допустимо отдельной будущей функцией с понятным предупреждением;
   сохранение блокировки между версиями требует отдельного проверенного протокола.
4. **Установка только через Rust-координатор.** Узкие команды check/download/install
   с идентификатором проверенного пакета; frontend не задаёт URL, путь, исполняемый
   файл или аргументы. Не выдавать прямой frontend доступ к установке в обход teardown.
   HTTPS, лимиты размера/времени/распаковки, проверенные редиректы release CDN;
   ошибки скачивания оставляют текущую версию и соединение работающими.
5. **Совместимый откат.** Сохранять прежний комплект и проверять локальный запуск новой
   версии без соединения с VPN. Не требовать успешного интернет-пробника для признания
   установки удачной. Предусмотреть ручное восстановление; миграции пользовательских
   данных должны быть совместимыми с откатом либо иметь отдельную безопасную копию.
   Не включать секреты, подписки или IP в update logs/артефакты.

На Windows plugin запускает установщик и вызывает `std::process::exit(0)`; обычный
`ExitRequested` RouteDeck с возможностью запретить выход нельзя считать гарантией
teardown. `on_before_exit` возвращает `()`, не отменяет установку: проверенный shutdown
должен завершиться **до** вызова install. Это вывод из официального исходника,
который нужно повторно проверить при выборе закреплённой версии зависимости.
[Tauri updater source, inspected commit 3a019435](https://github.com/tauri-apps/plugins-workspace/blob/3a01943572ba0d00909857a62588d06159e709ba/plugins/updater/src/updater.rs).

## Если выберем portable с заменой

- Начать с записи доступной только пользователю staging-папки и устойчивого журнала
  операции с ownership marker. Проверить подпись, архив, полный список файлов,
  helper digest и engine pins **до** остановки приложения.
- Отдельный обновляющий процесс из доверенного текущего комплекта ждёт завершения
  точного родительского процесса и собственных helper/engine; не завершает процессы
  по имени. Он знает только установочную папку и фиксированный контракт операции.
- На одном локальном томе сохранить старую папку как backup и переместить проверенную
  новую папку на её место. Два rename не являются атомарной транзакцией: журнал обязан
  восстанавливать каждый промежуточный шаг после сбоя питания. Сам updater запускается
  из отдельной доверенной временной папки, чтобы не держать заменяемую папку открытой.
- Отвергать `..`, абсолютные пути, дубликаты с разным регистром, ADS, zip bombs,
  reparse/junction/symlink и смену файлов между проверкой и запуском. Перезаписывать
  только доказанно принадлежащий релизу комплект; посторонние файлы не удалять.
  Для read-only/сетевой/защищённой папки предложить скачивание в новую папку;
  не повышать права незаметно. Старый комплект сохранять до подтверждения нового.

Windows sharing modes могут запретить rename/delete открытого файла. Отложенная
замена через `MoveFileEx(...DELAY_UNTIL_REBOOT)` требует прав администратора или
LocalSystem и только ставит операцию в очередь; это неудобная основа portable UX.
[Microsoft CreateFileW](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-createfilew),
[Microsoft MoveFileEx](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-movefileexw).

## Если выберем рекомендуемый NSIS

1. Добавить отдельный installer-артефакт, сохранив полный portable ZIP. Установка
   `currentUser`, прежний identifier `app.routedeck.desktop` и пользовательские данные.
   Проверить WebView2 bootstrapper/offline policy отдельно; без фоновой установки сервиса.
2. Перенести проверенный полный набор файлов в installer layout, сохранить sibling
   helper и `engine`/`xray`; стандартная bundler-сборка не должна незаметно пересобрать
   helper после встраивания его digest. При Authenticode сначала подписать helper,
   затем встроить hash его финальных байтов в GUI, подписать GUI, пересчитать provenance,
   собрать installer и последним подписать финальный update payload.
3. После source/ownership/integrity review закрепить конкретную версию updater,
   обновить оба lock-файла. Реализовать Rust-координатор download → verified shutdown
   → install; простое frontend `downloadAndInstall()` для RouteDeck недостаточно.
4. Release job после CI публикует versioned installer, `.sig`, валидный `latest.json`,
   portable и исходники/лицензии. Релизы не перезаписывать, prerelease не предлагать
   стабильному каналу. Проверить первый ручной переход portable → installer.

## Проверки будущей реализации

Детерминированные fixtures: неверная/пропавшая подпись, старый/чужой пакет,
обрезанная загрузка, traversal/ADS/reparse/zip bomb, чужие файлы, неверный helper,
отказ записи/rename, сбой после каждого шага, rollback и несовместимая миграция.
UI с synthetic IPC: прогресс, отмена, обновление при активном подключении откладывается,
ошибка teardown не запускает установщик, сохранение данных после перезапуска.
Installer/update smoke только в изолированной Windows VM после security review:
обычный пользователь, UAC отказ, заблокированный файл, перезапуск, rollback,
обновление N → N+1. Рабочий туннель разработчика для этих проверок не использовать.
